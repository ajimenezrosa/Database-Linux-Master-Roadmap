- Analizar el arranque actual y los arranques anteriores.

# Principio fundamental de recuperación

Durante una incidencia crítica debe evitarse realizar cambios impulsivos.

El procedimiento correcto es:

```text
Diagnosticar antes de modificar
```

No debe comenzarse con:

```bash
chmod -R 777 /
```

```bash
setenforce 0
```

```bash
xfs_repair -L
```

```bash
rm -rf /var/log/*
```

```bash
systemctl mask servicio
```

sin entender primero la causa.

---

# Síntoma, causa y consecuencia

Estos conceptos no son equivalentes.

## Síntoma

Es lo que el administrador observa.

Ejemplos:

```text
El sistema entra en Emergency
```

```text
El servicio no inicia
```

```text
El servidor tarda varios minutos en arrancar
```

---

## Causa

Es el problema real.

Ejemplos:

```text
UUID incorrecto en /etc/fstab
```

```text
Contexto SELinux inválido
```

```text
Volumen lógico inactivo
```

```text
/var está lleno
```

---

## Consecuencia

Es el impacto producido por la causa.

Ejemplos:

```text
local-fs.target no puede alcanzarse
```

```text
La aplicación no puede escribir sus logs
```

```text
multi-user.target no inicia completamente
```

---

# Ejemplo completo

```text
Síntoma:
El sistema entra en Emergency.

Causa:
La entrada de /datos en /etc/fstab utiliza un UUID inexistente.

Consecuencia:
mnt-datos.mount falla y local-fs.target no se completa.
```

# Metodología integral de recuperación

La recuperación puede dividirse en ocho etapas.

```text
1. Proteger el entorno
2. Identificar el modo actual
3. Recopilar evidencia
4. Clasificar el fallo
5. Aplicar la corrección mínima
6. Validar el cambio
7. Continuar o reiniciar
8. Documentar
```

---

# Etapa 1: proteger el entorno

Antes de modificar el sistema:

- Asegura acceso por consola.
- Confirma que estás en el servidor correcto.
- Comprueba la fecha y hora.
- Identifica la distribución.
- Verifica el nombre del host.
- Revisa si existen usuarios conectados.
- Determina si el sistema es productivo.
- Confirma si existe una copia de seguridad.
- Crea una instantánea si es una máquina virtual.
- Evita reinicios innecesarios.

# Etapa 4: clasificar el fallo

Los fallos pueden clasificarse en varias categorías.

| Categoría | Comandos principales |
|---|---|
| Montajes | `findmnt`, `mount -av`, `systemctl --failed --type=mount` |
| Dispositivos | `lsblk`, `blkid`, `dmesg` |
| LVM | `pvs`, `vgs`, `lvs`, `vgchange -ay` |
| Sistema de archivos | `e2fsck`, `xfs_repair` |
| Espacio | `df -h`, `df -i`, `du` |
| SELinux | `getenforce`, `ausearch`, `restorecon` |
| Servicios | `systemctl status`, `journalctl -u` |
| Unidades systemd | `systemctl cat`, `systemd-analyze verify` |
| Red | `ip`, `nmcli`, `networkctl` |
| Autenticación | `pwck`, `grpck`, `passwd`, `faillock` |
| Paquetes | `rpm -V`, `dnf reinstall` |
| Kernel/initramfs | `journalctl -k`, `dracut`, `/proc/cmdline` |

# Etapa 5: aplicar la corrección mínima

La corrección debe resolver la causa con el menor impacto posible.

Ejemplos:

| Problema | Corrección mínima |
|---|---|
| UUID incorrecto | Corregir únicamente la entrada |
| Disco opcional ausente | Agregar `nofail` si corresponde |
| Punto de montaje ausente | Crear el directorio |
| Contexto incorrecto | Ejecutar `restorecon` |
| Servicio defectuoso | Deshabilitar temporalmente |
| Configuración inválida | Restaurar archivo correcto |
| LV inactivo | Ejecutar `vgchange -ay` |
| `/var` lleno | Liberar o ampliar espacio |
| Ext4 inconsistente | Ejecutar `e2fsck` desmontado |
| XFS inconsistente | Ejecutar `xfs_repair` desmontado |

# Script de auditoría no destructiva

El siguiente script recopila información.

No intenta:

- Reparar sistemas de archivos.
- Editar `/etc/fstab`.
- Cambiar SELinux.
- Activar o desactivar servicios.
- Modificar LVM.
- Reiniciar el sistema.

---

# Archivo recomendado

```text
/usr/local/sbin/auditoria-rescue-emergency.sh
```

---

# Contenido del script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

readonly SCRIPT_NAME="$(basename "$0")"
readonly TIMESTAMP="$(date +%Y%m%d_%H%M%S)"
readonly HOSTNAME_SHORT="$(hostname -s 2>/dev/null || hostname)"
readonly DEFAULT_OUTPUT_DIR="/root/rescue-audit"
readonly OUTPUT_DIR="${1:-$DEFAULT_OUTPUT_DIR}"
readonly REPORT_FILE="${OUTPUT_DIR}/auditoria_${HOSTNAME_SHORT}_${TIMESTAMP}.log"

create_output_directory() {
    if ! mkdir -p "$OUTPUT_DIR"; then
        echo "ERROR: no se pudo crear $OUTPUT_DIR" >&2
        exit 1
    fi
}

print_header() {
    local title="$1"

    {
        echo
        echo "================================================================"
        echo "$title"
        echo "================================================================"
    } >> "$REPORT_FILE"
}

run_command() {
    local title="$1"
    shift

    print_header "$title"

    {
        echo "\$ $*"
        echo
        "$@"
        local status=$?
        echo
        echo "Código de salida: $status"
    } >> "$REPORT_FILE" 2>&1
}

run_shell_command() {
    local title="$1"
    local command="$2"

    print_header "$title"

    {
        echo "\$ $command"
        echo
        bash -o pipefail -c "$command"
        local status=$?
        echo
        echo "Código de salida: $status"
    } >> "$REPORT_FILE" 2>&1
}

check_root() {
    if [[ "$EUID" -ne 0 ]]; then
        echo "ADVERTENCIA: algunas comprobaciones requieren root." >&2
    fi
}

initialize_report() {
    {
        echo "AUDITORÍA RESCUE Y EMERGENCY"
        echo "Fecha: $(date --iso-8601=seconds)"
        echo "Servidor: $HOSTNAME_SHORT"
        echo "Script: $SCRIPT_NAME"
        echo "Usuario efectivo: $(id -un)"
        echo "UID efectivo: $EUID"
        echo "Directorio de salida: $OUTPUT_DIR"
        echo
        echo "Este informe es de solo diagnóstico."
        echo "No se ejecutan reparaciones automáticas."
    } > "$REPORT_FILE"
}

collect_basic_information() {
    run_command "FECHA Y HORA" date
    run_command "IDENTIDAD DEL SISTEMA" hostnamectl
    run_command "KERNEL" uname -a
    run_command "SISTEMA OPERATIVO" cat /etc/os-release
    run_command "UPTIME" uptime
    run_command "USUARIO EFECTIVO" id
    run_command "SESIONES ACTIVAS" who
}

collect_boot_information() {
    run_command "LÍNEA DE COMANDOS DEL KERNEL" cat /proc/cmdline
    run_command "ESTADO GENERAL DE SYSTEMD" systemctl is-system-running
    run_command "TARGET PREDETERMINADO" systemctl get-default

    run_shell_command \
        "TARGETS ACTIVOS" \
        "systemctl list-units --type=target --state=active --no-pager"

    run_command \
        "ESTADO DE RESCUE.TARGET" \
        systemctl status rescue.target --no-pager

    run_command \
        "ESTADO DE EMERGENCY.TARGET" \
        systemctl status emergency.target --no-pager

    run_command \
        "ARRANQUES REGISTRADOS" \
        journalctl --list-boots --no-pager
}

collect_failed_units() {
    run_command \
        "UNIDADES FALLIDAS" \
        systemctl --failed --no-pager

    run_command \
        "SERVICIOS FALLIDOS" \
        systemctl --failed --type=service --no-pager

    run_command \
        "MONTAJES FALLIDOS" \
        systemctl --failed --type=mount --no-pager
}

collect_journal_information() {
    run_command \
        "ERRORES DEL ARRANQUE ACTUAL" \
        journalctl -b -p err --no-pager

    run_command \
        "ADVERTENCIAS DEL ARRANQUE ACTUAL" \
        journalctl -b -p warning --no-pager

    run_shell_command \
        "ERRORES RELACIONADOS CON MONTAJES" \
        "journalctl -b --no-pager | grep -Ei 'mount|fstab|dependency|timeout|uuid|superblock' || true"

    run_shell_command \
        "ERRORES DE ALMACENAMIENTO" \
        "journalctl -k -b --no-pager | grep -Ei 'i/o error|medium error|buffer i/o|xfs|ext4|nvme|scsi|ata|device-mapper' || true"
}

collect_storage_information() {
    run_command "LSBLK" lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,FSVER,LABEL,UUID,MOUNTPOINTS
    run_command "LSBLK FSTYPE" lsblk -f
    run_command "BLKID" blkid
    run_command "FINDMNT" findmnt
    run_command "ESPACIO" df -hT
    run_command "INODOS" df -i
    run_command "SWAP" swapon --show
    run_command "TABLA DE PARTICIONES" fdisk -l
}

collect_fstab_information() {
    run_command "CONTENIDO DE FSTAB" cat /etc/fstab

    run_command \
        "VALIDACIÓN DE FSTAB" \
        findmnt --verify --verbose
}

collect_lvm_information() {
    run_command "PVS" pvs -a -o +devices
    run_command "VGS" vgs -a
    run_command "LVS" lvs -a -o +devices
    run_command "PVSCAN" pvscan
    run_command "VGSCAN" vgscan
    run_command "LVSCAN" lvscan
}

collect_selinux_information() {
    run_command "GETENFORCE" getenforce
    run_command "SESTATUS" sestatus

    run_shell_command \
        "CONFIGURACIÓN PERSISTENTE DE SELINUX" \
        "grep -E '^(SELINUX|SELINUXTYPE)=' /etc/selinux/config || true"

    run_shell_command \
        "EVENTOS AVC DEL ARRANQUE" \
        "ausearch -m AVC -ts boot 2>/dev/null || true"
}

collect_network_information() {
    run_command "INTERFACES" ip address
    run_command "RUTAS" ip route
    run_command "NETWORKMANAGER" systemctl status NetworkManager --no-pager
    run_command "NMCLI" nmcli device status
    run_command "RESOLV.CONF" cat /etc/resolv.conf
}

collect_package_information() {
    run_command "PAQUETES RPM CON PROBLEMAS DE BASE" rpm --verifydb

    run_shell_command \
        "ARCHIVOS RPMNEW Y RPMSAVE" \
        "find /etc -type f \\( -name '*.rpmnew' -o -name '*.rpmsave' \\) 2>/dev/null | sort"
}

collect_performance_information() {
    run_command "MEMORIA" free -h
    run_command "PROCESOS" ps auxf
    run_command "TOP CPU" ps -eo pid,ppid,user,%cpu,%mem,stat,comm,args --sort=-%cpu
    run_command "TOP MEMORIA" ps -eo pid,ppid,user,%cpu,%mem,stat,comm,args --sort=-%mem
}

collect_large_directories() {
    run_shell_command \
        "USO DE PRIMER NIVEL EN /VAR" \
        "du -xhd1 /var 2>/dev/null | sort -h"

    run_shell_command \
        "USO DE PRIMER NIVEL EN /" \
        "du -xhd1 / 2>/dev/null | sort -h"
}

collect_deleted_open_files() {
    if command -v lsof >/dev/null 2>&1; then
        run_command \
            "ARCHIVOS ELIMINADOS TODAVÍA ABIERTOS" \
            lsof +L1
    else
        print_header "ARCHIVOS ELIMINADOS TODAVÍA ABIERTOS"
        echo "lsof no está instalado." >> "$REPORT_FILE"
    fi
}

main() {
    check_root
    create_output_directory
    initialize_report

    collect_basic_information
    collect_boot_information
    collect_failed_units
    collect_journal_information
    collect_storage_information
    collect_fstab_information
    collect_lvm_information
    collect_selinux_information
    collect_network_information
    collect_package_information
    collect_performance_information
    collect_large_directories
    collect_deleted_open_files

    print_header "FIN DEL INFORME"
    echo "Auditoría finalizada: $(date --iso-8601=seconds)" >> "$REPORT_FILE"

    echo
    echo "Auditoría completada."
    echo "Informe generado:"
    echo "$REPORT_FILE"
}

main "$@"
```

# Matriz de selección del modo

| Situación | Modo recomendado |
|---|---|
| Servicio defectuoso | Rescue |
| Configuración de aplicación incorrecta | Rescue |
| Error en `/etc/fstab` | Emergency |
| Montaje crítico fallido | Emergency |
| Contraseña de root olvidada | `rd.break` |
| La raíz no se detecta en initramfs | Shell de dracut o ISO |
| Reparar raíz XFS | Medio de rescate |
| Activar LVM manualmente | Emergency o ISO |
| Restaurar contextos específicos | Rescue |
| Reetiquetado completo | Rescue y reinicio |
| Sistema completamente inaccesible | ISO de rescate |
| Daño físico de disco | Recuperación de hardware y respaldo |

# Resumen completo del capítulo

Los modos de recuperación forman parte esencial de la administración de sistemas RHEL.

```text
rescue.target
```

proporciona un entorno de mantenimiento relativamente completo.

```text
emergency.target
```

ofrece una shell mínima con muy pocas dependencias.

```text
rd.break
```

interrumpe el proceso dentro de `initramfs`, antes de que la raíz real se convierta en `/`.

# Comparación final

| Característica | Rescue | Emergency | `rd.break` |
|---|---|---|---|
| Etapa | systemd | systemd mínimo | initramfs |
| Servicios | Básicos | Muy pocos | Prácticamente ninguno |
| Montajes locales | Normalmente sí | Limitados | Raíz en `/sysroot` |
| Red | No garantizada | Normalmente no | No |
| Shell | Administrativa | Mínima | Shell de dracut |
| Uso principal | Mantenimiento | Fallo crítico | Recuperación temprana |
| `chroot` | Normalmente no | Normalmente no | Sí |
| Contraseña root | Puede solicitarse | Puede solicitarse | Método habitual de recuperación |
| Reparar raíz activa | No | No | No siempre; depende del montaje |
| Nivel de complejidad | Medio | Alto | Alto |

# Desafío final RHCSA

## Escenario

Administras un servidor RHEL que utiliza:

- XFS en `/`.
- XFS en `/var`.
- LVM para todos los volúmenes.
- SELinux en Enforcing.
- `multi-user.target` como target predeterminado.
- Un volumen opcional montado en `/copias`.
- Un servicio personalizado llamado `reportes.service`.

Después de un cambio, el servidor presenta estos síntomas:

1. Entra automáticamente en Emergency.
2. Muestra un tiempo de espera por un UUID inexistente.
3. `/var` no está montado.
4. El VG aparece, pero sus LVs están inactivos.
5. `/copias` corresponde a un disco USB que no está conectado.
6. `reportes.service` falla por acceso denegado.
7. El directorio `/srv/reportes` tiene un contexto SELinux incorrecto.
8. El target predeterminado fue cambiado accidentalmente a Rescue.
9. El sistema debe volver a iniciar normalmente.
10. Debes dejar evidencia completa de la intervención.

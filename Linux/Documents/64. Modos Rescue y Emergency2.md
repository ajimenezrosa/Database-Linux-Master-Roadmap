# Métodos para acceder a Rescue y Emergency

Existen varias formas de acceder a estos modos.

| Método | Rescue | Emergency | Requiere sistema iniciado |
|---|---:|---:|---:|
| Parámetro temporal desde GRUB | Sí | Sí | No |
| `systemctl rescue` | Sí | No | Sí |
| `systemctl emergency` | No | Sí | Sí |
| `systemctl isolate TARGET` | Sí | Sí | Sí |
| Entrada automática por fallo | Posible | Muy común | No |
| `systemd.unit=TARGET` | Sí | Sí | No |

---

# Método 1: iniciar Rescue desde GRUB2

Este método se utiliza cuando el sistema todavía no ha iniciado completamente.

## Paso 1: reiniciar

```bash
sudo systemctl reboot
```

---

## Paso 2: mostrar el menú de GRUB2

Durante el arranque, utiliza:

```text
Esc
```

En ciertos sistemas puede utilizarse:

```text
Shift
```

---

## Paso 3: seleccionar el kernel

Selecciona la entrada normal del sistema.

Ejemplo:

```text
Red Hat Enterprise Linux (5.14.0-503.el9.x86_64)
```

---

## Paso 4: editar la entrada

Presiona:

```text
e
```

---

## Paso 5: localizar la línea del kernel

Busca una línea que comience con:

```text
linux
```

o:

```text
linuxefi
```

---

## Paso 6: agregar el parámetro

Al final de la línea agrega:

```text
systemd.unit=rescue.target
```

Ejemplo conceptual:

```text
linux /vmlinuz-5.14.0-503.el9.x86_64 root=/dev/mapper/rhel-root ro rd.lvm.lv=rhel/root rhgb quiet systemd.unit=rescue.target
```

---

## Paso 7: iniciar

Presiona:

```text
Ctrl+x
```

También puede funcionar:

```text
F10
```

# Método 3: entrar en Rescue desde un sistema activo

Desde una consola local:

```bash
sudo systemctl rescue
```

Este comando intenta llevar el sistema a:

```text
rescue.target
```

---

# Confirmación interactiva

Dependiendo de la versión, el comando puede solicitar confirmación.

Ejemplo conceptual:

```text
Broadcast message from root:
The system is going down to rescue mode.
```

---

# Evitar confirmación

Puede existir una opción como:

```bash
sudo systemctl rescue --no-wall
```

`--no-wall` evita enviar mensajes de difusión, pero no debe utilizarse para ocultar un mantenimiento planificado.

---

# Método 4: entrar en Emergency desde un sistema activo

```bash
sudo systemctl emergency
```

Esto lleva el sistema a un entorno extremadamente mínimo.

---

# Riesgo de `systemctl emergency`

Puede detener:

- Red.
- SSH.
- Bases de datos.
- Aplicaciones.
- Montajes secundarios.
- Sesiones.
- Servicios administrativos.

Debe utilizarse únicamente desde una consola segura.

---

# Método 5: utilizar `systemctl isolate`

Rescue:

```bash
sudo systemctl isolate \
rescue.target
```

Emergency:

```bash
sudo systemctl isolate \
emergency.target
```

---

# Comparación de comandos

| Comando | Función |
|---|---|
| `systemctl rescue` | Método especializado para Rescue |
| `systemctl emergency` | Método especializado para Emergency |
| `systemctl isolate rescue.target` | Aísla directamente Rescue |
| `systemctl isolate emergency.target` | Aísla directamente Emergency |
| `systemctl start rescue.target` | Inicia Rescue sin aislamiento completo |
| `systemctl default` | Intenta volver al target predeterminado |

# Entrada automática en Emergency

Un sistema puede entrar en Emergency sin que el administrador lo solicite.

Causas habituales:

- Error en `/etc/fstab`.
- UUID inexistente.
- Disco ausente.
- Punto de montaje inválido.
- Sistema de archivos dañado.
- Dependencia `.mount` fallida.
- Volumen LVM no disponible.
- Disco cifrado no desbloqueado.
- Tiempo de espera agotado.
- Error crítico en un sistema de archivos.

---

# Mensaje común

```text
You are in emergency mode.
After logging in, type "journalctl -xb" to view system logs,
"systemctl reboot" to reboot,
or "exit" to continue bootup.
```

# Comprender `/etc/fstab`

El archivo:

```text
/etc/fstab
```

define sistemas de archivos que deben montarse automáticamente.

Formato general:

```text
dispositivo punto_montaje tipo opciones dump pass
```

Ejemplo:

```text
UUID=1111-2222 /datos xfs defaults 0 0
```

---

# Campos de `/etc/fstab`

| Campo | Descripción |
|---:|---|
| 1 | Dispositivo, UUID, LABEL o ruta |
| 2 | Punto de montaje |
| 3 | Tipo de sistema de archivos |
| 4 | Opciones |
| 5 | Copia con `dump` |
| 6 | Orden de comprobación con `fsck` |

---

# Ejemplo comentado

```text
UUID=abcd-1234 /datos xfs defaults 0 0
```

Interpretación:

```text
UUID=abcd-1234
```

identifica el sistema de archivos.

```text
/datos
```

es el punto de montaje.

```text
xfs
```

es el tipo.

```text
defaults
```

son las opciones.

```text
0
```

desactiva `dump`.

```text
0
```

indica que no se utiliza orden de `fsck` tradicional para esa entrada.

---

# Error de UUID

Ejemplo incorrecto:

```text
UUID=9999-INVALIDO /datos xfs defaults 0 0
```

Si ese UUID no existe, el sistema puede esperar y finalmente entrar en Emergency.

---

# Consultar UUID reales

```bash
lsblk -f
```

También:

```bash
blkid
```

Ejemplo:

```text
/dev/sdb1: UUID="a123-b456" TYPE="xfs"
```

---

# Comparar con `/etc/fstab`

```bash
grep -vE \
'^[[:space:]]*#|^[[:space:]]*$' \
/etc/fstab
```

Esto oculta comentarios y líneas vacías.

---

# Crear un respaldo antes de corregir

```bash
cp -a \
/etc/fstab \
/etc/fstab.bak
```

Con fecha:

```bash
cp -a \
/etc/fstab \
"/etc/fstab.$(date +%F-%H%M%S).bak"
```

---

# La raíz puede estar en solo lectura

Antes de editar:

```bash
findmnt /
```

Si aparece:

```text
ro
```

ejecuta:

```bash
mount -o remount,rw /
```

Verifica:

```bash
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS /
```

---

# Editar `/etc/fstab`

```bash
vi /etc/fstab
```

También:

```bash
nano /etc/fstab
```

si está instalado.

---

# Opción 1: corregir la entrada

Si conoces el UUID correcto:

```text
UUID=a123-b456 /datos xfs defaults 0 0
```

---

# Opción 2: comentar temporalmente

```text
# UUID=9999-INVALIDO /datos xfs defaults 0 0
```

Esto permite continuar el arranque mientras se investiga.

---

# Opción 3: utilizar `nofail`

```text
UUID=a123-b456 /datos xfs defaults,nofail 0 0
```

`nofail` permite que el arranque continúe aunque el dispositivo no esté disponible.

---

# Uso correcto de `nofail`

`nofail` es apropiado para:

- Discos externos.
- Recursos no críticos.
- Volúmenes opcionales.
- Almacenamiento que puede faltar temporalmente.

No debe utilizarse para ocultar fallos en volúmenes críticos.

---

# Opción `x-systemd.device-timeout=`

Permite controlar cuánto espera `systemd` por un dispositivo.

Ejemplo:

```text
UUID=a123-b456 /datos xfs defaults,nofail,x-systemd.device-timeout=10s 0 0
```

---

# Opción `x-systemd.automount`

Puede crear un montaje bajo demanda.

Ejemplo:

```text
UUID=a123-b456 /datos xfs defaults,x-systemd.automount 0 0
```

Debe utilizarse solo cuando se comprende su efecto.

---

Utiliza:

```bash
findmnt --verify
```

Salida correcta conceptual:

```text
Success, no errors or warnings detected
```

---

# Validar y mostrar información detallada

```bash
findmnt --verify --verbose
```

---

# Probar montajes

```bash
mount -av
```

Opciones:

```text
-a
```

intenta montar las entradas de `/etc/fstab`.

```text
-v
```

muestra detalles.

---

# Advertencia con `mount -a`

`mount -a` no necesariamente desmonta ni vuelve a montar sistemas ya activos.

Su objetivo principal es intentar montar entradas pendientes.

---

# Recargar systemd después de cambiar fstab

```bash
systemctl daemon-reload
```

Esto es importante porque `systemd` genera unidades `.mount` a partir de `/etc/fstab`.

---

# Probar nuevamente

```bash
mount -av
```

```bash
systemctl --failed
```

---

# Continuar el arranque

```bash
systemctl default
```

Si el sistema vuelve a Emergency, todavía existe un problema.

---

# Flujo de recuperación de `/etc/fstab`

```text
Emergency mode
      │
      ▼
journalctl -xb
      │
      ▼
systemctl --failed
      │
      ▼
lsblk -f y blkid
      │
      ▼
Respaldar /etc/fstab
      │
      ▼
Remontar / en rw
      │
      ▼
Corregir entrada
      │
      ▼
findmnt --verify
      │
      ▼
mount -av
      │
      ▼
daemon-reload
      │
      ▼
systemctl default
```

## Situación

`systemctl --failed` muestra:

```text

```

```text

```

## Diagnóstico

```bash

```

```bash
blkid
```

```bash

```

---

## Corrección

Respaldar:

```bash
cp -a /etc/fstab /etc/fstab.bak
```

Editar:

```bash
vi /etc/fstab
```

Reemplazar el UUID incorrecto.

Validar:

```bash
findmnt --verify
```

Probar:

```bash

```

```text

```

# Caso práctico 6: ruta con espacios

Una ruta con espacios debe representarse adecuadamente.

Ejemplo:

```text
/mnt/Mis Datos
```

En `/etc/fstab` se representa normalmente como:

```text
/mnt/Mis\040Datos
```

Ejemplo:

```text
UUID=a123-b456 /mnt/Mis\040Datos xfs defaults 0 0
```

# Unidades `.mount` generadas por systemd

`systemd` convierte entradas de `/etc/fstab` en unidades de montaje.

Ejemplo:

```text
/mnt/datos
```

se convierte en:

```text
mnt-datos.mount
```

---

# Regla de nombres

```text
/
```

corresponde a:

```text
-.mount
```

```text
/home
```

corresponde a:

```text
home.mount
```

```text
/mnt/datos
```

corresponde a:

```text
mnt-datos.mount
```

# Buenas prácticas

✔ Utilizar GRUB para cambios temporales.

✔ No convertir Rescue o Emergency en targets permanentes.

✔ Mantener acceso a consola.

✔ Revisar `journalctl -xb` antes de cambiar archivos.

✔ Respaldar `/etc/fstab` antes de editar.

✔ Utilizar UUID reales obtenidos con `blkid` o `lsblk -f`.

✔ Verificar el estado de montaje de `/`.

✔ Utilizar `findmnt --verify`.

✔ Probar con `mount -av`.

✔ Ejecutar `systemctl daemon-reload`.

✔ Restablecer estados fallidos después de corregir.

✔ Utilizar `nofail` únicamente para recursos opcionales.

✔ No ocultar fallos críticos con opciones permisivas.

✔ Ejecutar `sync` antes de reiniciar.

✔ Documentar la causa y la solución.

# Errores comunes

## Editar `/etc/fstab` sin respaldo

Una segunda equivocación puede empeorar la recuperación.

---

## Reiniciar sin probar `mount -av`

El sistema puede entrar nuevamente en Emergency.

---

## No ejecutar `daemon-reload`

`systemd` puede conservar unidades generadas con información anterior.

---

## Utilizar un UUID copiado de otro servidor

Cada sistema de archivos tiene identificadores propios.

---

## Usar `/dev/sdb1` sin necesidad

Los nombres `/dev/sdX` pueden cambiar.

Se recomienda utilizar:

```text
UUID=
```

o:

```text
LABEL=
```

---

## Agregar `nofail` a un volumen crítico

El sistema podría continuar sin datos esenciales.

---

## Ejecutar `fsck` sobre un sistema XFS montado

XFS utiliza herramientas específicas y no debe repararse como ext4.

---

## Reparar un sistema de archivos montado

Las herramientas de reparación suelen requerir que el sistema esté desmontado.

---

## Usar `chmod 777`

Expone archivos y no corrige la causa real.

---

## Entrar en Emergency desde SSH

La conexión probablemente se perderá.
